Algorithms

Linear Search

O(n)

Linear search checks every item one by one, starting from the beginning, until it finds the value you're looking for or reaches the end and concludes it isn't there. It works on any list, sorted or not, but it can be slow on large ones.

The Attendance Sheet Analogy

Picture an exam attendance sheet where names were written down in whatever order students walked in, not alphabetically, not by registration number, just random arrival order. If you want to check whether your name is on that sheet, there's only one honest way to do it: start from the top and read every single name, one after another, until you find yours or reach the bottom and realize you're not listed. You can't skip around or guess a shortcut, because the list has no order to exploit. That's exactly what linear search does, and exactly why it works on absolutely any list — sorted or not, at the cost of potentially checking every single item.

Where linear search shows up in real software

Anywhere data isn't sorted, or is too small to bother sorting, linear search is often the simplest and most practical choice.

Everyday Software

Ctrl+F — Find in Document

When you press Ctrl+F and type a word, your browser or word processor doesn't know in advance where that word appears — the document's text isn't sorted alphabetically, it's just written in whatever order the author typed it. So the program checks each word from the start, in order, until it finds a match — exactly like the visualizer above.

Worked example: searching for "fox" in "the quick brown fox jumps"

Unsorted Contact Lists

An address book that was never sorted alphabetically has to be searched name by name, there's no shortcut without first organizing the data.

Practical Choice

Small Datasets

For a handful of items, sorting first and using a faster search algorithm often costs more time than just checking each item directly, so linear search remains the practical choice even when smarter options exist.
