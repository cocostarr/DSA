Data Structures

Stack

LIFO

A stack is a data structure that holds items in a single line, where you can only add or remove from one end called the top. It follows one strict rule: the last item added is always the first one removed.

The Bukateria Analogy

Imagine a bukateria where plates of food are stacked on top of each other, waiting to be served. When a new plate of jollof rice is ready, it goes on top of the pile — you don't slide it in at the bottom. And when a customer is served, the attendant takes the plate sitting right on top, the most recently added one and never the one buried underneath. That's exactly how a stack works: the last item you add is the first one you remove. In computing, we call this LIFO — Last In, First Out.

Where stacks show up in real software

Stacks aren't just a classroom idea. They quietly run underneath tools you use every day. Here are three places you'll find them at work.

Compilers

CERS — Compiler Expression/Recursion Stack

When a compiler reads your code, it uses a stack to keep track of where it is, which expression it's currently evaluating, and which function call it needs to return to once the current one finishes. Every open bracket, every nested function call, every unfinished calculation gets pushed onto this internal stack until it's resolved, then popped off once it's done. Without a stack, the compiler would have no way to "remember its place" in deeply nested code.

Compilers & Calculators

Expression Evaluation

Calculators and compilers often convert expressions into postfix notation (numbers first, operators after) because it removes the need for brackets and makes evaluation simple with a stack: read left to right, push numbers, and whenever you hit an operator, pop the last two numbers, apply the operator, and push the result back.

Worked example: 3 4 2 * +

Token Action Stack after
3 Push 3 [3]
4 Push 4 [3, 4]
2 Push 2 [3, 4, 2]
* Pop 2, Pop 4 → 4*2=8, push 8 [3, 8]
+ Pop 8, Pop 3 → 3+8=11, push 11 [11]

Final result: 11 which matches (3 + (4 * 2)) in normal infix notation.

Programming Languages

Recursion Implementation

Every time a function calls itself, the program doesn't forget what it was doing. It pushes the current call onto the call stack and starts a new one. Once a call finishes, it gets popped off, and control returns to exactly where the previous call left off. This is also why deeply recursive functions can crash with a "stack overflow" — too many calls pushed on, with nowhere left to put them.

Worked example: factorial(3)

Step Action Call stack (top → bottom)
1 Call factorial(3) [factorial(3)]
2 factorial(3) calls factorial(2) [factorial(2), factorial(3)]
3 factorial(2) calls factorial(1) [factorial(1), factorial(2), factorial(3)]
4 factorial(1) returns 1, pops off [factorial(2), factorial(3)]
5 factorial(2) returns 2*1=2, pops off [factorial(3)]
6 factorial(3) returns 3*2=6, pops off []

Final result: 6
