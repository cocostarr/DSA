Linked List

Dynamic Size

A linked list is a chain of nodes, where each node holds a value and a pointer to the next node in line. Unlike an array, its items aren't stored in one continuous block of memory — they can live anywhere, connected only by these pointers.

The Danfo Bus Analogy

Think of a linked list like passengers sitting in a danfo bus, one behind the other in a single row. Each passenger only knows who is sitting directly in front of them — they have no idea who's behind. If you want to find the fifth passenger, you can't just jump there; you have to start from the first person and ask each one, "who's next?" until you reach them. That's exactly how a linked list works: each node only knows about the next node, so getting anywhere means traversing from the start — there's no shortcut like an array's instant index access. The upside is that adding or removing a passenger anywhere in the row is easy — you just adjust who's pointing to whom.

Where linked lists show up in real software

Because they grow and shrink easily without shifting everything else around, linked lists show up anywhere data needs to change size constantly.

Media

Music & Video Playlists

Hitting "Next" or "Previous" on a playlist is essentially traversing a linked list — each track only needs to know what comes after it, and songs can be added or removed from the queue without reshuffling the whole playlist.

Operating Systems

Memory Management

Free blocks of memory in a computer aren't stored in one continuous strip — they're scattered around. Operating systems track them using linked lists, since blocks are constantly being claimed and released as programs run.

Applications

Undo & Redo History

Many apps use a doubly linked list — where each node points both forward and backward — to move between undo and redo states, letting you step back and forth through your action history in either direction.

Undo & Redo History

Many apps use a doubly linked list — where each node points both forward and backward — to move between undo and redo states. A pointer marks your "current" position in the history; pressing undo moves it one node back, redo moves it one node forward. Typing a brand new action after undoing discards everything ahead of the pointer, since that "future" no longer exists.

Worked example: type "A", type "B", type "C", then undo twice, then type "D"

Action History Pointer
Type "A" A A
Type "B" A ⇄ B B
Type "C" A ⇄ B ⇄ C C
Undo A ⇄ B ⇄ C B
Undo A ⇄ B ⇄ C A
Type "D" A ⇄ D (B, C discarded) D

This is why redo stops working once you type something new after undoing — the "future" nodes B and C get cut off from the list.

Media

Music & Video Playlists

Hitting "Next" or "Previous" on a playlist is essentially traversing a linked list. A "Now Playing" pointer marks the current song; pressing Next moves the pointer forward to the next node, and Previous moves it backward. Songs can be added to or removed from the queue at any point without reshuffling the whole playlist — only the pointers around that node need to change.

Worked example: playlist of 3 songs, press Next, Next, then Previous

Action Playlist Now Playing
Start Rush ⇄ Calm Down ⇄ Unavailable Rush
Next Rush ⇄ Calm Down ⇄ Unavailable Calm Down
Next Rush ⇄ Calm Down ⇄ Unavailable Unavailable
Previous Rush ⇄ Calm Down ⇄ Unavailable Calm Down

The playlist itself never changes shape here — only the "Now Playing" pointer moves across it, which is exactly how traversal works in a linked list.
