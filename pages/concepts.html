Understanding Big-O Notation

Every page on this site labels its structures and algorithms with something like O(n) or O(log n). This is called Big-O notation, and it's simply a way to describe how an algorithm's speed changes as the amount of data grows — without getting distracted by exact numbers or specific hardware.

O(1)

Constant Time

Takes the same amount of time no matter how much data there is. Example: Array Access — jumping straight to index 5 takes one step whether the array has 10 items or 10 million.

O(log n)

Logarithmic Time

Gets slightly slower as data grows, but very gradually — each step eliminates half of what's left. Example: Binary Search.

O(n)

Linear Time

Time grows in direct proportion to the data — double the data, double the work. Example: Linear Search, checking every item once.

O(n²)

Quadratic Time

Time grows much faster than the data — double the data, and the work roughly quadruples. Example: Bubble Sort, comparing every pair against every other pair.

The general order from fastest to slowest, for large amounts of data: O(1) < O(log n) < O(n) < O(n²)

Data Structures at a Glance

A quick summary of every structure covered on this site — useful for revision right before an exam.

Structure Access Insert Delete Ordering
Array O(1) O(n) O(n) By index
Linked List O(n) O(1)* O(n) By pointer chain
Stack O(n) O(1) O(1) LIFO (top only)
Queue O(n) O(1) O(1) FIFO (front/rear only)

*Insert at the head of a linked list is O(1); inserting at an arbitrary position still requires traversing to it first, which is O(n).

Beyond This Site

EduViz DSA focuses on linear structures and foundational algorithms — the building blocks everything else is built on. Once you're comfortable here, these non-linear structures are the natural next step, and GeeksForGeeks has excellent visual guides for each:

🌳 Trees

Hierarchical structures where each node can have multiple children — used in file systems, databases, and decision-making algorithms.

🕸️ Graphs

Networks of connected nodes — the foundation behind maps, social networks, and route-finding apps.

🔑 Hash Tables

Structures that map keys directly to values for near-instant lookup — used everywhere from caches to databases.
