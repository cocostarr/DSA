Binary Search

O(log n)

Binary search only works on a sorted list but in exchange, it's dramatically faster than linear search. Instead of checking every item, it jumps to the middle, decides which half the value must be in, and throws the other half away completely cutting the search space in half every step.

The Dictionary Analogy

Remember the attendance sheet from Linear Search, names written down in random arrival order, forcing you to check one by one? A dictionary is the complete opposite. Every word is arranged alphabetically, and that single fact changes everything about how you search it. Nobody looks up "zebra" by starting at page 1 — you flip roughly to the middle, see you've landed in the M's, realize Z comes after M, and immediately ignore the entire first half of the book. Then you repeat the trick on the remaining half, and the half after that, until you land on the page. Each flip throws away roughly half of what's left. That's binary search: it only works because the data has order to exploit the exact thing linear search's random attendance sheet didn't have.

Where binary search shows up in real software

Anywhere data is sorted and the dataset is large, binary search's speed advantage becomes too valuable to ignore.

Software Engineering

Git Bisect

When a bug appears somewhere in a project's history but nobody knows which commit introduced it, git bisect finds it using binary search. Commits are naturally "sorted" by time, so Git checks out the middle commit between a known-good and known-bad point, you test it, and Git throws away half the history based on your answer repeating until the exact commit is found.

Worked example: 8 commits, bug introduced at commit 6

Range Commit tested Result
1 – 8 4 Good — bug not here yet
5 – 8 6 Bad — bug is present
5 – 6 5 Good — bug not here yet
6 – 6 6 Bad — commit 6 is the culprit

Only 4 tests were needed to pinpoint the exact commit out of 8 — checking each one individually would have taken up to 8 tests instead.

Databases

Database Indexing

Databases keep sorted index structures (often B-trees, a relative of binary search) so that looking up a record among millions of rows takes only a handful of comparisons instead of scanning the whole table.

Games

Number Guessing Games

The optimal strategy for a "guess a number between 1 and 100" game is binary search: guess 50, get told higher or lower, guess the new midpoint, and repeat, solving it in at most 7 guesses no matter what the number is.
